# ZENITH — Architecture & Implementation Artifact Register

## Purpose

This register consolidates the architecture, ontology, UX, governance, gate, research, security and implementation artifacts produced before and during the initial ZENITH repository bootstrap.

The imported artifacts are retained as historical/source evidence. Existing canonical ZENITH governance and contracts remain authoritative unless a reviewed ADR supersedes them.

## Architecture baseline

- Master Architecture Blueprint v1.0 — one shared Past Intelligence Core; many independent experience surfaces; South India-first and globally interoperable.
- Final Architecture Readiness Review v1.0 — conditional GO for implementation after contract closure.
- Implementation Contract Freeze v1.0 — PostgreSQL/PostGIS, CIDOC CRM-aligned interoperability, evidence/provenance chain, policy control plane, federation and audit boundaries.
- Architecture Decision Register v1.0 — decisions, implementation gate and initial SLOs.
- Architecture Gate Test Specification v1.0 — executable acceptance criteria before production readiness.
- Architecture Gate Execution Report/Register v1.0 — design-level gates verified; runtime gate remains open until real implementation exists.
- Representative Journey Gate Review/Register v0.1 — public discovery, research, sensitive heritage, AI, federation and tenant-isolation journeys.

## Important distinction

Source artifacts created under the earlier working name “Past Intelligence Core” are retained for continuity. They are not evidence that a production ZENITH runtime existed at the time of their creation. The security kernel and gate harness explicitly state their non-production status.

## Import rule

Do not create duplicate domain logic from these artifacts. Convert them into canonical ZENITH contracts, migrations, tests or ADRs only through an explicit review/verification step.
